## What is a compiler

### Compiler

Compiler 是一個可以把一個 Program 從「某個 Source Language」翻譯成「某個 Machine Language」，並且翻譯要是 **等價的**（自動機可證明），簡而言之功能就是

$$
\texttt{Automatic translation} + \texttt{Optimization}
$$

<Fig src="/images/compiler/ch01-intro/compiler.webp" caption="Compiler" width={90} />

> Compiler 即便知道哪裡錯誤也不能自行修正，而應該提醒哪裡錯了

1950's 需要用打孔的的模式，無法驗證，因此有人想設計一種自動驗證翻譯的軟體，讓打孔變得順利，因此設計了 Assembly Language，以及相應的驗證翻譯軟體 **Assembler**

而現今，CPU 功能越來越多 Pipeline 更複雜，Compiler 也變得複雜

<Fig src="/images/compiler/ch01-intro/modern-architecture.webp" caption="Modern Architecture" width={70} />

### Interpreter

Compiler 會把 program compile 成一個 executable file，而 Interpreter 則是把自己當成 executable file，用 simulate 的方式執行，效能較差

### Hybrid Translator

合併 Compiler, Interpreter，例如 Java，先把 program compile 成 bytecode，然後用 JVM (Interpreter) 去模擬一下，最後再動態 compile 成 executable file，這種模式叫做 **JIT (Just In Time compilation)**，JIT compiler 會把 hot code (一直重複執行的 code) 做 optimize 的 compilation，加速運行

<Fig src="/images/compiler/ch01-intro/hybrid-translator.webp" caption="Hybrid Translator" width={80} />


<Aside type="note" title="Fallacy 1">
很多人可能說去寫 assembly 會比寫 high level language 快，但 modern compiler 已經可以做到超高效能，不建議再手刻，並且 register allocation 這個問題很容易出錯，因此甚至 compiler 出來的東西會比你手刻快，並且 Scalability 比較好
</Aside>

<Aside type="note" title="Fallacy 2">
在現在的 Compilation 技術中，我們有很多 runtime compilation 技術，因此你的 program 其實是 dynamically (runtime) 的 compile 的
1. GPU, CPU 執行分配，OpenCL 等一系列需要 adaptive system
2. Machine dependency code

現今技術大約可以分為兩大種類
- Static Compilation
    * Typical Compilers
    * Profile-Guided Compilation
    * Link-time optimization
    * Post-Link time optimization
    * AOT (Ahead-of-Time) Compilation
- Dynamic Compilation
    * JIT (Just-in-Time) Compilation
    * Adaptive Compilation
    * Dynamic/Adaptive Optimization
</Aside>

## Structure of a compiler

我們大致可以把 compiler 分成 **Analysis**, **Synthesis** 兩個部分，而又可以細分成
- **Analysis** 分析 program 是否 runable
    - **Lexical** analysis：抓出關鍵字（**token**: 變數、關鍵字等）
    - **Syntax** analysis：檢查語法是否正確
    - **Semantic** Analysis：分成 **type**（變數類型）, **scope**（變數作用區域）等一系列 Semantic 是否正確，也就是檢查宣告正確性
- **Synthesis** 分析有什麼方法可以優化以及生成 Machine code
    - Optimization
    - Code Generation

可以按照 compiler 的運行機制分成很多種，例如：

**Syntax-Directed Compiler** 是一種可以把每一行 code 一行一行進行編譯直接執行的 compiler，按照每一行文法的 rule 寫好就好了


<Fig src="/images/compiler/ch01-intro/structure-of-a-syntax-directed-compiler.webp" caption="Structure of a Syntax-Directed Compiler" width={80} />

**Multi-Pass Compiler** 則會先把 high-level language 先轉換成一種 Intermediate language，經過多輪優化後才變成 Target code

<Fig src="/images/compiler/ch01-intro/structure-of-multi-pass-compilation.webp" caption="Structure of Multi-Pass Compilation" width={80} />

### Lexical Analysis

```txt
Pay := Base + Rate * 160
```

Lexical analysis 會抓出很多 token
- `id`：`Pay`, `Base`, `Rate` are identifiers
- `asign`：`:=` is assignment symbol
- `op`：`+` and `*` are operators
- `num`：`160` is a number

假設今天有以下句子
```txt
Pay := Base + Rate @ * 160
```

但我們有規定這個語言沒有 `@` 這個 token，**Scanner** 就會在這個階段把他抓出來

### Syntax analysis

即便每個字元都可以被拆成 token，還是有可能有無法解讀的問題，例如以下這個例子

```txt
Pay := Base + Rat^^E * 160
```

`^^` 可能在這個語言是某種 token，但他前後可能不能接兩個變數，在這個例子裡，他的前後分別是 `Rat`, `e` 兩個變數，所以會被回報成 Syntax Error

### Static Semantics

**Static Semantics** 就是在我需要 compiler 裡面寫死就可以檢查到的語意，比如說 **Attribute grammars** 是一種熱門的定義方法

#### Imprecise Semantics Challenges

比如說 Pascal 對 short-circuit 並沒有很明確的定義，所以會出現一些奇怪的問題，但這並不是 semantic 上的錯，而是 unexpectable result


<Aside type="tip" title="Example">
short-cut 的意思是在一些 `if`, `switch` 判斷時，假設前面的 case （不）成立，那便不需要執行後面的，e.g. C language 裡面有對 short-cut 做定義
```c
int gv = 1;

bool foo() { gv++; }

int main() {
    if (1 == 1 || foo())
        printf("%d\n", gv);
    return 0;    
}
```
呼叫 `foo()` 會執行 `gv++`，使全域變數 `gv` 的值增加 1。不過，邏輯 OR 運算子 `||` 採用 **short-circuit evaluation**：它會先求值左運算元；若結果為真，就能確定整個運算式為真，因此不會再求值右運算元。

在這個例子中，左側的 `1 == 1` 為真，因此右側的 `foo()` 不會被呼叫，`gv++` 也就不會執行。`gv` 仍維持初始值 `1`，所以程式輸出的是 **`1`，而不是 `2`**。
</Aside>


#### Java

Java 定義了 compiler semantic，例如，function 不可以有不回傳 value 的情況，像下面這個 code 就是 illegal 的

```java
public static int subr(int b) {
    if (b!=0) return b+100; 
}
```

以下這個 code 雖然人類知道他必定有回傳值，但 compiler 還是會報錯

```java
public static int subr(int b) {
     if (b!=0) return b+100; 
     else if (10*b == 0) return 1; 
}
```

#### Cross-Compilation

Compiler 的 source code 本來就是開源的，而要在什麼架構上運行是 compile 出來的 executable file 的問題 

用一份 source code，可以先後做到兩件事（假設我們是要寫出一個 C compiler
1. 在 x86 的 machine 上面的用原生 compiler 編譯（e.g. `gcc`），會得到一個可以在 x86 machine 上 compile 出 RISC-V machine code 的 compiler，我們稱它為 **Cross-Compiler**
2. 把同一份 code 在 x86 machine 上送進 Cross-compiler，得到一個新的 Compiler，也就是一份，由 RISC-V machine code 寫成的 Native RISC-V compiler

<Fig src="/images/compiler/ch01-intro/construct-a-c-compiler-through-cross-compiler.webp" caption="Construct a C compiler through Cross-Compiler" width={80} />
