# Process Control & IPC

以 `ls | more` 為例，shell 要建立 processes、連接 I/O，最後取得結束狀態。這章分別看 process 的建立與管理，以及交換資料的 IPC

## Booting 

### Bootstrapping

**Bootstrapping** 是從開機到啟動系統的過程：

```text noLineNumbers
BIOS / UEFI → bootloader → kernel → System services and user programs
```

1. **Firmware** 初始化硬體，交給 bootloader
2. **Bootloader** 載入 kernel
3. **Kernel** 初始化 memory management、devices、process management，再啟動 system services

課堂的傳統 Unix 流程先進入 single-user mode 做檢查與維護，再進入 multiuser mode 啟動登入、網路等服務；實際流程依系統而定

**Special process**

課堂使用的傳統 Unix 配置：

- **`PID 0`**: Swapper / scheduler，最早的 kernel 執行環境
- **`PID 1`**: `init`，啟動 system services、接手與回收失去 parent 的 processes
- **`PID 2`**: `pagedaemon`，處理分頁相關工作

編號與名稱依實作而異。下圖的重點是 process tree：`init` 啟動服務，登入服務啟動 shell，shell 再建立執行指令的 children

<Fig src="/images/sp/ch06-process/bootstrapping.webp" caption="Unix process tree" />

### Process Control Block (PCB)

**PCB** 是 kernel 保存 process metadata 的資料結構，先看它記錄的 states：

| State | 意義 |
| --- | --- |
| **New** | 正在建立 |
| **Ready** | 等待 CPU |
| **Running** | 正在 CPU 上執行 |
| **Waiting** | 等待 I/O 或其他事件 |
| **Terminated** | 已結束 |

<Fig src="/images/sp/ch06-process/process-control-block-1.webp" caption="Process state transitions" />

例如 terminal 還沒有輸入時，process 進入 waiting；資料準備好才回到 ready，等排程後繼續執行

PCB 還記錄：

- **PID / PPID**: 自己與 parent 的身分
- **Program Counter、CPU registers**: 保存執行位置與狀態
- **CPU scheduling information**: Priority 等排程資訊
- **Memory-management information**: Virtual memory 的對應
- **Accounting information**: CPU time 等資源紀錄
- **I/O status information**: 開啟的檔案等 I/O 狀態

<Fig src="/images/sp/ch06-process/process-control-block-2.webp" caption="Fields of the proc structure" />

### Process table

**Process table** 管理所有 processes 的 PCB，概念上每個 entry 對應一個 process，實作不一定是連續陣列

要找某個 process 的 children，就看哪些 PPID 等於它的 PID，也可以用下面的指令觀察：

```bash
ps -e -o pid,ppid,stat,comm
```

PID 在 process 結束並完成回收後可以重新使用

### Context switch

**Context switch** 把 CPU 上的 process 換成另一個：

<Fig src="/images/sp/ch06-process/context-switch-1.webp" caption="Context switch between processes" />

1. 保存 P0 的 registers、Program Counter
2. 把 P0 放回 ready queue 或對應的等待佇列
3. 載入 P1 的狀態與記憶體對應，繼續執行

**進入 kernel mode 不一定發生 context switch**，system call 若能立即完成，可以直接回到原本的 process

<Aside type="note" title="">

**Process Scheduling Queue**

- **Job queue**: 系統內所有 processes 的集合
- **Ready queue**: 等待 CPU
- **Device queues**: 等待對應裝置的 I/O

<Fig src="/images/sp/ch06-process/context-switch-2.webp" caption="Ready queue and I/O queues" />

Queues 串接的是管理資訊；I/O 完成後，對應的 process 回到 ready

</Aside>

### Process Content & Metadata

- **Metadata**: PCB 裡的 PID、state、registers 等管理資訊
- **Content**: Virtual memory 裡的指令與資料

<Fig src="/images/sp/ch06-process/process-content-and-metadata.webp" caption="Process metadata and virtual memory" />

- **Text**: 程式指令
- **Initialized data / BSS**: Global、static variables，依初始化方式區分
- **Stack**: Function call 的 stack frames、local variables、返回資訊
- **Heap**: `malloc()` 配置的空間

圖中的成長方向是簡化配置，實際依系統而定。`free()` 讓空間可被 allocator 再利用，不保證立刻還給 kernel

### Process Creation & Termination

- **`fork()`**: 建立 child process
- **`exec()` 家族**: 替換目前 process 執行的 program
- **`wait()` 家族**: 取得 child 狀態、回收已結束的 child

<Fig src="/images/sp/ch06-process/process-creation-and-termination-1.webp" caption="Process creation with fork and exec" />

<Aside type="note" title="">

**`pid_t fork(void)`**

成功時 **Call once, return twice**，parent 和 child 都從 `fork()` 之後繼續：

| 回傳值 | 意義 |
| --- | --- |
| `-1` | 建立失敗，沒有 child，檢查 `errno` |
| `0` | Child process |
| 大於 `0` | Parent process，值是 child PID |

```c noLineNumbers
pid_t pid = fork();

if (pid < 0) {
    /* 建立失敗 */
} else if (pid == 0) {
    /* child 的工作 */
} else {
    /* parent 的工作，pid 是 child PID */
}
```

<Fig src="/images/sp/ch06-process/process-creation-and-termination-2.webp" caption="Parent and child after fork" />

Child 不會從 `main()` 重跑，`0` 也不是它的 PID；查自己的身分用 `getpid()`，查 parent 用 `getppid()`

</Aside>

**Virtual Memory 的運作**

立刻複製全部 physical pages 成本很高，尤其 child 可能馬上 `exec()`。因此使用 **Copy-on-write (COW)**，先讓兩者的 virtual pages 共用 physical pages：

<Fig src="/images/sp/ch06-process/process-creation-and-termination-3.webp" caption="Shared pages before copy-on-write" />

Process 1 要修改 page C 時，才複製該頁；Process 2 繼續使用原本那份：

<Fig src="/images/sp/ch06-process/process-creation-and-termination-4.webp" caption="Private page after copy-on-write" />

所以 **普通變數的修改仍各自獨立**。Virtual address space 未使用的洞也不必配置實體記憶體，詳見 [fork(2)](https://man7.org/linux/man-pages/man2/fork.2.html)

<Aside type="tip" title="Example of `vfork()`">

先用 `fork()` 對照普通變數與 standard I/O buffer 的行為：

```c title="fork_buffer.c"
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>

static int glob = 6;

int main(void) {
    int var = 88;
    pid_t pid;

    if (write(STDOUT_FILENO, "a write to stdout\n", 18) != 18) {
        perror("write");
        return 1;
    }
    printf("before fork\n");

    pid = fork();
    if (pid < 0) {
        perror("fork");
        return 1;
    }
    if (pid == 0) {
        glob++;
        var++;
        printf("child: glob = %d, var = %d\n", glob, var);
        exit(0);
    }

    while (waitpid(pid, NULL, 0) < 0) {
        if (errno != EINTR) {
            perror("waitpid");
            return 1;
        }
    }
    printf("parent: glob = %d, var = %d\n", glob, var);
    return 0;
}
```

Parent 用 `waitpid()` 等 child，固定輸出順序。直接在一般 terminal 執行：

```text noLineNumbers
a write to stdout
before fork
child: glob = 7, var = 89
parent: glob = 6, var = 88
```

Child 改變 `glob`、`var`，parent 的值不變。接著把輸出導向檔案：

```bash
./a.out > temp.out
cat temp.out
```

`stdout` 使用 fully buffered 時：

```text noLineNumbers
a write to stdout
before fork
child: glob = 7, var = 89
before fork
parent: glob = 6, var = 88
```

`before fork` 還在 user space buffer 時被一起複製，兩邊結束時各送出一次；`write()` 已把資料交給 kernel，所以只有一次。若在 `fork()` 前先成功 `fflush(stdout)`，就能避免重複輸出

</Aside>

<Aside type="note" title="Practice 1">

```c noLineNumbers
void forkfunc(void) {
    if (fork() && fork())
        fork();
    write(STDOUT_FILENO, "*\n", 2);
}
```

假設所有 `fork()` 成功，`&&` 左邊為假就不算右邊，最後共有 **4 個 `*`**：

1. 第一次的 child 得到 `0`，跳過右邊與 `if`，印一次
2. 原本的 parent 做第二次 `fork()`，第二個 child 不進 `if`，印一次
3. 原本的 parent 進入 `if` 再分成兩個，各印一次

</Aside>

<Aside type="note" title="Practice 2">

```c noLineNumbers
void forkfunc(void) {
    if (fork() || fork())
        fork();
    write(STDOUT_FILENO, "*\n", 2);
}
```

同樣假設成功，`||` 左邊為真就不算右邊，最後共有 **5 個 `*`**：

1. 第一次的 parent 直接進入 `if`，再分成兩個，各印一次
2. 第一次的 child 做右邊的 `fork()`；其中得到正值者進入 `if`，再分成兩個，各印一次
3. 第二次的 child 兩邊都是 `0`，不進 `if`，印一次

</Aside>

### **Normal cases in fork**

**Parent、child 沒有固定的執行先後**。Parent 可以立即等待，也能先做自己的工作，再取得 child 結果。Process 數量與資源有上限，課堂用 `CHILD_MAX` 說明相關限制

**Inherited properties**

- Real / effective UID、GID、supplementary groups
- Current working directory、root directory、`umask`
- Environment、resource limits
- Signal dispositions、signal mask
- File descriptors

兩者各有自己的 fd table，但對應 fd 可指向同一個 **open file description**，共享 offset 與 file status flags；關閉 child 的 fd 不會刪掉 parent 的 fd

**Differences on properties**

- Child 有自己的 PID，PPID 指向 parent
- CPU time、資源使用紀錄重新計算
- Pending signals、`alarm()` 剩餘時間不繼承
- 傳統 process-associated record locks 不繼承，其他 lock 類型另有規則

<Fig src="/images/sp/ch06-process/normal-cases-in-fork.webp" caption="Inherited and changed properties after fork" />

<Aside type="note" title="**Usage of fork**">

- **分工作**：Server 建立 child 處理連線，繼續執行原本程式
- **換 program**：Shell 建立 child，再 `exec()` 指定程式

`posix_spawn()` 也提供建立 process 並執行程式的功能，但內部不保證用 `fork()` 加 `exec()` 實作，詳見 [posix_spawn(3)](https://man7.org/linux/man-pages/man3/posix_spawn.3.html)

</Aside>

<Aside type="note" title="**vfork**">

**`vfork()`** 讓 child 暫時借用 parent 的 address space，預期立刻 `exec()` 或 `_exit()`。以 Linux 為例，呼叫它的 parent thread 暫停到 child 成功 `exec()` 或結束，不必等新 program 執行完

Child 不應修改普通變數、從目前函式 `return` 或呼叫 `exit()`。課堂修改 `glob`、`var` 是觀察共用現象，不能當成合法用法；`vfork()` 也已不在 POSIX.1-2008 標準內，詳見 [vfork(2)](https://man7.org/linux/man-pages/man2/vfork.2.html)

</Aside>

<Aside type="tip" title="Example of `vfork()`">

Child 直接 `exec()`，失敗才 `_exit()`；parent 的等待與錯誤處理在此省略：

```c noLineNumbers
pid_t pid = vfork();

if (pid < 0) {
    /* parent 處理建立失敗 */
} else if (pid == 0) {
    execl("/bin/echo", "echo", "hello", (char *)NULL);
    _exit(127);  /* exec 失敗才會走到這裡 */
} else {
    /* child 已經 exec 或結束，parent 繼續 */
}
```

因為連 stack 都可能共用，child 不呼叫 `printf()` 或 `exit()`，避免操作 parent 的 library 狀態。Process 身分與 fd 繼承仍是兩個 processes 各自的資訊

</Aside>

###   Deadlock

**Deadlock** 是互相等待、沒有任何一方能繼續。例如 child 等 parent 修改變數，parent 卻因 `vfork()` 暫停：

<Aside type="note" title="">

```text noLineNumbers
parent 呼叫 vfork()
    ↓
parent 暫停，等待 child exec 或結束
    ↓
child 等待 parent 把 var 從 88 改成 100
    ↓
但 parent 還沒恢復執行，永遠到不了 var = 100
```

Child 的 busy waiting 等不到 parent 執行。這只是流程示意，不是合法的 `vfork()` 共用變數用法

</Aside>

資源 deadlock 的常見條件是 mutual exclusion、hold and wait、no preemption、circular wait

### Process Termination

Normal termination 指透過正常介面結束，**不代表工作成功**，例如 `exit(1)` 仍屬於 normal termination

**Normal termination**

<Fig src="/images/sp/ch06-process/process-termination-1.webp" caption="Process termination and exit handlers" />

`main()` 回傳後，start-up routine 做相當於 `exit(status)` 的處理：

| 寫法 | 行為 |
| --- | --- |
| 從 `main()` `return status` | 正常結束，執行 `exit()` 清理 |
| `exit(status)` | 呼叫 exit handlers、送出 standard I/O buffer，再結束 |
| `_exit(status)` / `_Exit(status)` | 不呼叫 exit handlers、不送出 standard I/O buffer |

普通 function 的 `return` 只回到 caller。`_exit()` 仍由 kernel 關閉 fds、釋放資源與保存結束狀態，詳見 [exit(3)](https://man7.org/linux/man-pages/man3/exit.3.html)、[_exit(2)](https://man7.org/linux/man-pages/man2/_exit.2.html)

**Abnormal termination**

因 signal 被終止，例如 `abort()` 產生 `SIGABRT`，後面用 status macros 區分

**`int atexit(void (*func)(void));`**

註冊無參數、回傳 `void` 的 exit handler，成功回傳 `0`。Handlers 按**註冊的相反順序**執行：

```c noLineNumbers
atexit(cleanup_a);
atexit(cleanup_b);
/* exit() 時先執行 cleanup_b，再執行 cleanup_a */
```

`_exit()` 或 signal 直接終止不會走這套清理流程

**`pid_t wait(int *statloc)`**

```c noLineNumbers
int status;
pid_t ended = wait(&status);
```

- 回傳取得狀態的 child PID，把結果寫入 `status`；不需要結果可傳 `NULL`
- 有已結束但未回收的 child 就直接取得，否則等待
- 沒有可等待的 child：`-1`、`ECHILD`
- 被 signal 中斷：可能回傳 `-1`、`EINTR`，可重試

**`pid_t waitpid(pid_t pid, int *statloc, int op)`**

可以指定等待對象：

| `pid` | 對象 |
| --- | --- |
| 大於 `0` | 指定 PID 的 child |
| `-1` | 任意 child |
| `0` | 同 process group 的 child |
| 小於 `-1` | Process group ID 為 `-pid` 的 child |

`op` 決定觀察的狀態與等待方式：

- `0`: 等待結束
- `WNOHANG`: 無符合狀態時立即回傳 `0`，不代表 child 結束
- `WUNTRACED`: 也回報停止
- `WCONTINUED`: 也回報從停止繼續執行

一般只能等待自己的 children

<Aside type="note" title="Terminate Status">

`status` 是編碼，要先判斷再取值：

| 判斷 | 成立後取得 |
| --- | --- |
| `WIFEXITED(status)` | `WEXITSTATUS(status)`：Exit status，低 8 bits |
| `WIFSIGNALED(status)` | `WTERMSIG(status)`：終止的 signal |
| `WIFSTOPPED(status)` | `WSTOPSIG(status)`：停止的 signal |
| `WIFCONTINUED(status)` | 已繼續執行 |

<Fig src="/images/sp/ch06-process/process-termination-2.webp" caption="Macros for child process status" />

`WCOREDUMP(status)` 判斷是否產生 core dump，跨較舊系統可用 `#ifdef WCOREDUMP`。停止與繼續的回報需搭配相應 options，基本的 `waitpid(..., 0)` 主要等結束

</Aside>

<Aside type="tip" title="Example of wait()">

第一個 child 正常結束，第二個 child 用 `raise()` 把 `SIGKILL` 送給自己：

```c title="wait_status.c"
#include <errno.h>
#include <signal.h>
#include <stdio.h>
#include <sys/wait.h>
#include <unistd.h>

static void pr_exit(int status) {
    if (WIFEXITED(status)) {
        printf("normal termination, exit status = %d\n",
               WEXITSTATUS(status));
    } else if (WIFSIGNALED(status)) {
        printf("terminated by signal %d\n", WTERMSIG(status));
    } else if (WIFSTOPPED(status)) {
        printf("stopped by signal %d\n", WSTOPSIG(status));
    } else if (WIFCONTINUED(status)) {
        printf("continued\n");
    }
}

int main(void) {
    for (int i = 0; i < 2; i++) {
        pid_t pid = fork();
        int status;

        if (pid < 0) {
            perror("fork");
            return 1;
        }
        if (pid == 0) {
            if (i == 0)
                _exit(7);
            raise(SIGKILL);
            _exit(1);
        }

        while (waitpid(pid, &status, 0) < 0) {
            if (errno != EINTR) {
                perror("waitpid");
                return 1;
            }
        }
        pr_exit(status);
    }
    return 0;
}
```

Parent 分別取得 exit status `7` 與 `SIGKILL` 編號。其他 signal 可用 `abort()` 或 `raise(SIGFPE)` 觀察；C 的整數除以 `0` 是未定義行為，不能保證產生 `SIGFPE`

</Aside>

<Aside type="note" title="process die">

Child 結束通常會通知 parent **`SIGCHLD`**。它的 default action 雖是 ignore，仍不代表自動回收 child；明確設定 `SIG_IGN` 或 `SA_NOCLDWAIT` 另有回收規則，詳見 [wait(2)](https://man7.org/linux/man-pages/man2/waitpid.2.html)

</Aside>

## Zombie & Orphan

### Zombie  

**Zombie** 是已結束、狀態尚未被 parent 取得的 child。主要資源已釋放，kernel 保留 PID、status 與資源紀錄，`ps` 通常顯示 `Z` 或 `<defunct>`

由 parent 呼叫 `wait()` / `waitpid()` 回收；`kill -9` 無法再殺一次已結束的 process。短暫出現不一定有問題，長期未回收才會累積紀錄

### Orphan

**Orphan** 是自己還活著、parent 先結束，kernel 會安排新的 parent。傳統 Unix 由 `init` 接手，Linux 也可能由 ancestor subreaper 接手，所以 PPID 不保證變成 `1`，詳見 [PR_SET_CHILD_SUBREAPER(2)](https://man7.org/linux/man-pages/man2/PR_SET_CHILD_SUBREAPER.2const.html)

<Aside type="note" title="Existence of Zombie Process">

Parent 不一定立刻取結果，所以 kernel 暫存狀態，也不能在回收前把 PID 分配給別人。**停止的 child 還活著，不是 zombie**；回報停止狀態不等於回收

</Aside>

**Double fork**

透過兩次 `fork()` 把真正工作的 grandchild 交給新 parent 管理：

<Fig src="/images/sp/ch06-process/orphan.webp" caption="Process creation with double fork" />

1. Parent 建立 child，child 再建立 grandchild
2. Child 結束，grandchild 被安排新的 parent
3. 原本的 parent 回收 child；grandchild 由接手者回收

<Aside type="tip" title="Example of double fork">

```c title="double_fork.c"
#include <errno.h>
#include <stdio.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    pid_t child = fork();
    int status;

    if (child < 0) {
        perror("fork");
        return 1;
    }
    if (child == 0) {
        pid_t grandchild = fork();

        if (grandchild < 0)
            _exit(1);
        if (grandchild > 0)
            _exit(0);

        /* 只有 grandchild 會走到這裡 */
        dprintf(STDOUT_FILENO, "grandchild: pid = %ld, parent = %ld\n",
                (long)getpid(), (long)getppid());
        _exit(0);
    }

    while (waitpid(child, &status, 0) < 0) {
        if (errno != EINTR) {
            perror("waitpid");
            return 1;
        }
    }
    return WIFEXITED(status) && WEXITSTATUS(status) == 0 ? 0 : 1;
}
```

印 PPID 時，第一個 child 可能尚未結束，也可能已被接手；加 `sleep(2)` 不能保證同步。Double fork 常用在 daemon 流程，但 foreground / background 還涉及 session、process group 與 terminal 設定

</Aside>

**`int waitid(idtype_t idtype, id_t id, siginfo_t *infop, int options);`**

- `P_PID`、`P_PGID`、`P_ALL`: 指定 child、process group 裡的 child、任意 child
- `WEXITED`、`WSTOPPED`、`WCONTINUED`: 選擇狀態
- `WNOHANG`: 不等待
- `WNOWAIT`: 查看後保留成可再次等待的狀態，這次不完成回收

成功回傳 `0`，child PID 在 `infop->si_pid`；`WNOHANG` 沒結果也回傳 `0`，不能只看回傳值

**`pid_t wait3(int *statloc, int op, struct rusage *rusage);`**,
**`pid_t wait4(pid_t pid, int *statloc, int op, struct rusage *rusage);`**

除了狀態，還透過 `rusage` 取得 CPU time、記憶體使用統計。這是 BSD 系列介面，Linux 也支援，但不是 POSIX 通用 API

### Race Condition

**Race condition** 是結果依賴不確定的執行順序。例如 parent 和 child 在同一個 terminal 逐字輸出：

<Aside type="tip" title="Example">

```c title="race_output.c"
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>

static void charatatime(const char *str) {
    for (; *str != '\0'; str++)
        putchar((unsigned char)*str);
}

int main(void) {
    pid_t pid;

    setbuf(stdout, NULL);
    pid = fork();
    if (pid < 0) {
        perror("fork");
        return 1;
    }
    if (pid == 0) {
        charatatime("output from child\n");
        exit(0);
    }

    charatatime("output from parent\n");
    while (waitpid(pid, NULL, 0) < 0) {
        if (errno != EINTR) {
            perror("waitpid");
            return 1;
        }
    }
    return 0;
}
```

可能得到交錯的字元：

```text noLineNumbers
ooutput from child
utput from parent
```

`setbuf(stdout, NULL)` 關閉 standard I/O buffer，讓字元分別送出：

<Fig src="/images/sp/ch06-process/race-condition-1.webp" caption="Standard I/O buffer and kernel data structures" />

兩者的 `FILE` objects 各自獨立，但底下是同一個 terminal，kernel 可在兩次輸出間切換。印完才 `waitpid()` 只確保回收，沒有規定誰先印

</Aside>

<Aside type="note" title="Example of double fork">

固定時間的 `sleep()` 不能保證 parent 已結束，下面的寫法也不通用：

```c noLineNumbers
while (getppid() != 1)
    sleep(1);
```

這是每秒檢查的 polling，不是持續佔用 CPU 的 busy loop，但在 subreaper 接手、PPID 不變成 `1` 時可能永遠等不到

</Aside>

**`int execl(const char *pathname, const char *arg0, … /* (char *) 0 */);`**
**`int execv(const char *pathname, char *const argv[]);`**
**`int execle(const char *pathname, const char *arg0, … /* (char *) 0, char *const envp[] */);`**
**`int execve(const char *pathname, char *const argv[], char *const envp[]);`**

**`exec()` 替換 program，保留 process 的 PID**，重新配置 text、data、heap、stack 並執行新的 start-up routine。成功不回傳，失敗回傳 `-1` 並設定 `errno`

| 字母 | 意義 |
| --- | --- |
| **`l`** | List，逐個列出參數，以 `(char *)NULL` 結尾 |
| **`v`** | Vector，傳入以 `NULL` 結尾的 `argv` 陣列 |
| **`e`** | 自己提供 environment `envp` |
| 沒有 **`e`** | 使用 caller 的 environment |

下面都執行 `echo hello`：

```c noLineNumbers
execl("/bin/echo", "echo", "hello", (char *)NULL);

char *args[] = {"echo", "hello", NULL};
execv("/bin/echo", args);
```

第一個參數是載入的 pathname，後面的 `"echo"` 是新程式的 `argv[0]`

<Aside type="note" title="Environment">

**Environment** 是 `NAME=value` 字串集合，`exec()` 依傳入資料建立新的 command-line arguments 與 environment：

<Fig src="/images/sp/ch06-process/race-condition-2.webp" caption="Process image replaced by exec" />

`extern char **environ` 指向以 `NULL` 結尾的指標陣列，各元素指向環境變數字串：

<Fig src="/images/sp/ch06-process/race-condition-3.webp" caption="Environment list and environment strings" />

部分系統支援 `main(int argc, char **argv, char **envp)`，第三個參數不是 ISO C 保證的介面。讀取或修改環境變數可用 `getenv()`、`setenv()`、`unsetenv()`

`PATH` 用 `:` 分隔搜尋目錄，例如 `/bin:/usr/bin:/usr/local/bin`

</Aside>

**`int execlp(const char *filename, const char *arg0, … /* (char *) 0 */);`**
**`int execvp(const char *filename, char *const argv[]);`**

**`p`** 使用 `PATH` 搜尋，例如 `execlp("ls", "ls", (char *)NULL)`。Filename 包含 `/` 時直接使用該 path；shell built-ins 也不會由 `execvp()` 自動執行

遇到 `ENOEXEC` 時，`p` 家族會嘗試交給 `/bin/sh` 解讀，不代表任意 binary 都能變成 script，詳見 [exec(3)](https://man7.org/linux/man-pages/man3/exec.3.html)

<Aside type="note" title="">

<Fig src="/images/sp/ch06-process/race-condition-4.webp" caption="Relationship between exec functions" />

在 Linux 等實作中，library 整理 `argv`、搜尋 `PATH`、補上 `environ`，最後交給底層的 `execve()` system call

</Aside>

**Close on exec**

Fd 通常跨過 `exec()` 保留，shell 才能先接好 `stdin`、`stdout` 給新程式。要在成功 `exec()` 時關閉某個 fd，就設 **`FD_CLOEXEC`**：

<Fig src="/images/sp/ch06-process/race-condition-5.webp" caption="FD_CLOEXEC in the file descriptor table" />

```c noLineNumbers
int flags = fcntl(fd, F_GETFD);
/* 實際使用時要檢查兩次 fcntl() 是否失敗 */
fcntl(fd, F_SETFD, flags | FD_CLOEXEC);
```

也能在 `open()` 加 `O_CLOEXEC` 一次設定。Flag 存在個別 fd，`fork()` 會繼承；`exec()` 失敗則不會因此關閉，詳見 [execve(2)](https://man7.org/linux/man-pages/man2/execve.2.html)

<Aside type="caution" title="為何要分開 fork(), exec()">

Child 可以只執行原程式，也能先設定 fd、cwd，再 `exec()` 新程式：

```c title="fork_exec.c"
#include <errno.h>
#include <stdio.h>
#include <sys/wait.h>
#include <unistd.h>

int main(void) {
    pid_t pid = fork();
    int status;

    if (pid < 0) {
        perror("fork");
        return 1;
    }
    if (pid == 0) {
        execl("/bin/echo", "echo", "hello from exec", (char *)NULL);
        perror("execl");
        _exit(127);
    }

    while (waitpid(pid, &status, 0) < 0) {
        if (errno != EINTR) {
            perror("waitpid");
            return 1;
        }
    }
    if (WIFEXITED(status))
        return WEXITSTATUS(status);
    return 1;
}
```

`echo` 載入失敗才會走到 `perror()`、`_exit(127)`；parent 等待的始終是同一個 child PID

</Aside>

## IPC (Inter-process Communication)

**IPC** 讓 processes 交換資料或通知；這裡的 pipe、FIFO 都透過 kernel 傳送，使用 `read()`、`write()`

### Pipe

**`int pipe(int filedes[2]);`**

建立單向通道，成功回傳 `0`，並填入：

- **`filedes[0]`**: 讀端
- **`filedes[1]`**: 寫端

<Fig src="/images/sp/ch06-process/pipe-1.webp" caption="Read and write ends of a pipe" />

資料經過 kernel 的 pipe buffer，讀走後不保留，也不能 `lseek()`。**先 `pipe()` 再 `fork()`**，child 就能繼承兩端 fd：

<Fig src="/images/sp/ch06-process/pipe-2.webp" caption="Pipe descriptors after fork" />

要由 parent 傳給 child：parent 關讀端、保留寫端；child 關寫端、保留讀端

<Fig src="/images/sp/ch06-process/pipe-3.webp" caption="Pipe from parent to child" />

未使用的端點也要關閉，例如 reader 留著自己的寫端，kernel 就仍認為有 writer，導致預期的 EOF 不出現

Blocking mode 的規則：

| 狀況 | 行為 |
| --- | --- |
| 有資料 | `read()` 取現有資料，不必湊滿要求數量 |
| 空，但仍有 writer | `read()` 等待 |
| 空間足夠 | `write()` 放入 buffer，不必等 reader |
| 空間不足 | `write()` 可能等待 |

可設 `O_NONBLOCK`，搭配 `select()` / `poll()`。`ls | more` 則由 shell 建立 pipe 和兩個 processes，用 `dup2()` 接好 standard I/O，再分別 `exec()`

<Aside type="note" title="">

- **所有寫端關閉**：讀完剩餘資料後得到 `0`（EOF）
- **所有讀端關閉**：再寫入會有 `SIGPIPE`；忽略或處理後返回，寫入失敗並設定 `EPIPE`

**Pipe 是 byte stream，沒有 message boundaries**。兩次寫入 `abc`、`def`，可能一次讀到 `abcdef`，也可能分多次取得

單次 `write()` 要求不超過 **`PIPE_BUF`** 時，成功寫入不會與其他 writers 交錯；non-blocking 放不下則失敗為 `EAGAIN`。更大的寫入可能 partial write；這個上限不是 pipe 總容量，也不保證一次 read 得到完整訊息，詳見 [pipe(7)](https://man7.org/linux/man-pages/man7/pipe.7.html)

</Aside>

<Aside type="tip" title="Example of pipe()">

Parent 寫入一句話，child 讀到 EOF。`write_all()` 處理 partial write 和 `EINTR`：

```c title="pipe_message.c"
#include <errno.h>
#include <stdio.h>
#include <sys/wait.h>
#include <unistd.h>

static int write_all(int fd, const char *buf, size_t size) {
    while (size > 0) {
        ssize_t n = write(fd, buf, size);
        if (n < 0) {
            if (errno == EINTR)
                continue;
            return -1;
        }
        if (n == 0) {
            errno = EIO;
            return -1;
        }
        buf += n;
        size -= (size_t)n;
    }
    return 0;
}

int main(void) {
    int fd[2];
    int status;
    pid_t pid;

    if (pipe(fd) < 0) {
        perror("pipe");
        return 1;
    }
    pid = fork();
    if (pid < 0) {
        perror("fork");
        return 1;
    }
    if (pid == 0) {
        char buf[128];
        close(fd[1]);

        for (;;) {
            ssize_t n = read(fd[0], buf, sizeof(buf));
            if (n == 0)
                break;
            if (n < 0) {
                if (errno == EINTR)
                    continue;
                perror("read");
                _exit(1);
            }
            if (write_all(STDOUT_FILENO, buf, (size_t)n) < 0) {
                perror("write");
                _exit(1);
            }
        }
        close(fd[0]);
        _exit(0);
    }

    close(fd[0]);
    const char message[] = "hello world\n";
    int failed = write_all(fd[1], message, sizeof(message) - 1) < 0;
    if (failed)
        perror("write");
    close(fd[1]);

    while (waitpid(pid, &status, 0) < 0) {
        if (errno != EINTR) {
            perror("waitpid");
            return 1;
        }
    }
    return failed || !WIFEXITED(status) || WEXITSTATUS(status) != 0;
}
```

Parent 要先送完資料、關閉寫端才 `waitpid()`，否則 child 等 EOF、parent 等 child，可能互相卡住

</Aside>

<Aside type="caution" title="Avoiding Race Condition">

用通知規定 parent 先印，child 才印；兩個方向各用一條 pipe：

- `TELL_CHILD()` / `WAIT_PARENT()`：Parent 通知，child 等待
- `TELL_PARENT()` / `WAIT_CHILD()`：Child 通知，parent 等待

<Fig src="/images/sp/ch06-process/pipe-4.webp" caption="Parent-child synchronization with two pipes" />

```c title="pipe_sync.c"
#include <errno.h>
#include <stdio.h>
#include <stdlib.h>
#include <sys/wait.h>
#include <unistd.h>

static int pfd1[2], pfd2[2];

static void fail(const char *name) {
    perror(name);
    exit(1);
}

static void send_byte(int fd, char value) {
    ssize_t n;
    do {
        n = write(fd, &value, 1);
    } while (n < 0 && errno == EINTR);
    if (n != 1) {
        if (n == 0)
            errno = EIO;
        fail("send notification");
    }
}

static void receive_byte(int fd, char expected) {
    char value;
    ssize_t n;
    do {
        n = read(fd, &value, 1);
    } while (n < 0 && errno == EINTR);
    if (n < 0)
        fail("read notification");
    if (n != 1 || value != expected) {
        fprintf(stderr, "unexpected notification or EOF\n");
        exit(1);
    }
}

static void TELL_WAIT(void) {
    if (pipe(pfd1) < 0 || pipe(pfd2) < 0)
        fail("pipe");
}

static void TELL_CHILD(pid_t pid) {
    (void)pid;
    send_byte(pfd1[1], 'p');
}

static void WAIT_PARENT(void) {
    receive_byte(pfd1[0], 'p');
}

static void TELL_PARENT(pid_t pid) {
    (void)pid;
    send_byte(pfd2[1], 'c');
}

static void WAIT_CHILD(void) {
    receive_byte(pfd2[0], 'c');
}

static void charatatime(const char *str) {
    for (; *str != '\0'; str++)
        putchar((unsigned char)*str);
}

int main(void) {
    int status;
    pid_t pid;

    setbuf(stdout, NULL);
    TELL_WAIT();
    pid = fork();
    if (pid < 0)
        fail("fork");
    if (pid == 0) {
        close(pfd1[1]);
        close(pfd2[0]);
        WAIT_PARENT();
        charatatime("output from child\n");
        TELL_PARENT(getppid());
        close(pfd1[0]);
        close(pfd2[1]);
        _exit(0);
    }

    close(pfd1[0]);
    close(pfd2[1]);
    charatatime("output from parent\n");
    TELL_CHILD(pid);
    WAIT_CHILD();
    close(pfd1[1]);
    close(pfd2[0]);

    while (waitpid(pid, &status, 0) < 0) {
        if (errno != EINTR)
            fail("waitpid");
    }
    return !WIFEXITED(status) || WEXITSTATUS(status) != 0;
}
```

Pipe 版本依 fd 通知，保留的 `pid` 參數不使用。執行順序是：

```text noLineNumbers
parent 印完 → 傳送 'p' → child 讀到通知後才印
child 印完  → 傳送 'c' → parent 收到後完成等待與回收
```

Child 先執行就等待 `read()`；通知先送則留在 buffer，之後仍能讀取，不必猜 `sleep()` 時間

</Aside>

### FIFO

**FIFO (Named pipe)** 有 pathname，讓分別啟動的 processes 找到同一條通道，不必透過 `fork()` 繼承 fd

**`int mkfifo(const char *pathname, mode_t mode);`**

只建立命名入口，成功回傳 `0`、失敗回傳 `-1`；mode 受 `umask` 影響，之後再 `open()` 取得 fd

在一個 terminal 建立並讀取：

```bash
mkfifo /tmp/sp-demo.fifo
cat /tmp/sp-demo.fifo
```

另一個 terminal 寫入：

```bash
printf 'hello from FIFO\n' > /tmp/sp-demo.fifo
```

`cat` 讀完資料、writer 關閉後會看到 EOF。資料只經過 kernel buffer，不寫成 disk 內容；沒有使用者開啟後也不保留資料，但 **pathname 仍存在**

另一端尚未開啟時，`open()` 的行為：

| 開啟方式 | 結果 |
| --- | --- |
| `O_RDONLY` | 等待 writer |
| `O_WRONLY` | 等待 reader |
| `O_RDONLY \| O_NONBLOCK` | 立即取得讀端 |
| `O_WRONLY \| O_NONBLOCK` | 失敗，`ENXIO` |

開啟後遵循 pipe 的 I/O 規則；空且仍有 writer 時，non-blocking `read()` 得到 `EAGAIN`。Linux 可用 `O_RDWR` 同開兩端，但非 POSIX 保證，也會影響 EOF，詳見 [fifo(7)](https://man7.org/linux/man-pages/man7/fifo.7.html)

<Aside type="tip" title="Example">

用 `tee` 把 `prog1` 的同一份輸出分送給 `prog2`、`prog3`：

<Fig src="/images/sp/ch06-process/fifo-1.webp" caption="Output duplication with tee and FIFO" />

```bash
mkfifo fifo1
prog3 < fifo1 &
prog1 < infile | tee fifo1 | prog2
```

`tee` 的 standard output 接 `prog2`，寫入 `fifo1` 的資料交給 `prog3`。這是主動複製分送；兩個 readers 直接讀同一條 FIFO 只會分走資料，不會各得完整副本

</Aside>

<Aside type="tip" title="Socket">

Server 準備 **well-known FIFO** 收集各個 client 的 requests：

<Fig src="/images/sp/ch06-process/fifo-2.webp" caption="Client requests through a well-known FIFO" />

一筆 request 用不超過 `PIPE_BUF` 的單次 `write()` 送出，避免 writers 交錯，server 仍需解析 message boundaries。Response 則送到各個 client 專屬的 FIFO：

<Fig src="/images/sp/ch06-process/fifo-3.webp" caption="Client-server communication with FIFOs" />

Request 帶上回覆位置，避免其他 client 讀走 response；也要安排好兩端的 `open()` 順序，避免互相等待

</Aside>
